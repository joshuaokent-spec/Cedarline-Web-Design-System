# Project Brief — Cedarline Web Design System

## Design challenge

The first three Cedarline projects intentionally solve different UX problems:

- customer claim reporting;
- employee claims operations;
- policy and coverage information architecture.

Without shared standards, those products can drift into inconsistent color usage, button hierarchy, form behavior, spacing, focus treatment, error messaging, table patterns, and voice.

The design-system problem is:

> **What shared rules and reusable components should make Cedarline web experiences consistent, accessible, maintainable, and recognizable without forcing every product to use the same layout or information density?**

## Goals

- establish a coherent visual foundation;
- standardize high-frequency interaction patterns;
- make accessibility requirements part of component definitions;
- reduce one-off design decisions;
- support both consumer and enterprise contexts;
- document content and responsive standards;
- create a handoff artifact that designers and developers can use together.

## Non-goals

This portfolio project does not claim to be:

- a production package distributed to real teams;
- the result of an enterprise governance council;
- a replacement for product-specific user research;
- a complete component library covering every possible interaction.

## System principles

### Calm under pressure
Insurance users may be stressed. Visual hierarchy and status communication should reduce uncertainty.

### Plain language first
Formal insurance terms remain available, but interfaces should help people reach them.

### Accessible by default
Accessibility behavior is part of a component's definition, not an optional enhancement.

### System, not sameness
Shared tokens and interaction rules create consistency while allowing different densities and layouts.

### Explain state
Selected, disabled, loading, warning, error, and success states should be explicit and understandable without relying on color alone.
